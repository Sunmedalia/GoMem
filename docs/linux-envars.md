# Linux 进程环境变量（开发预览）

`linux.envars` 对应固定基线 `linux.envars.Envars`。它遍历活动任务，跳过 `PF_KTHREAD`（`0x00200000`）内核线程，并通过该任务自己的页表读取 `mm_struct.env_start` 到 `env_end`。完整能力尚未验收。

```sh
bin/gomem analyze linux.envars --image memory.raw --symbols exact.json.xz \
  --dtb 0x1605000 --os linux --offline --param pid=322
```

`max-env` 默认 8192 字节，与基线的环境区上限相同。超过上限、页表缺页或地址空间不可用时，该任务写出诊断并让整个任务失败，不把缺失内容显示成空环境。基线会跳过这些任务并继续成功。

变量按原始 NUL 切分，再按第一个 `=` 分开。键和值保留原始字节，展示字符串使用替换字符处理非法 UTF-8。某一项没有 `=` 时停止该任务的后续变量，并保留这项原始字节；这与基线遇到覆写后的环境区时中止解析一致，但基线不保留失败项。无用户 `mm` 且不是内核线程的任务单独报告，不用进程名猜测环境。

选定 Debian 3.2 x64 采集有 39 个内核线程、94 个用户任务。1,402 条变量的 PID、PPID、命令名、键和值与固定基线顺序一致。另有 11 个基线未输出的任务：`init` 和 `atd` 的环境页不在页表中，`dovecot` 为 8,419 字节超过默认上限，其余 8 个（包括两个 `avahi-daemon`）的首项没有分隔符。因此原生任务失败，已发出的变量行仍然保留。[机器验证记录](linux-envars-validation.json)

此结果只覆盖这份旧 x64 采集和合成页表。现代内核、32 位、线程环境复用和时间线仍未验收。
